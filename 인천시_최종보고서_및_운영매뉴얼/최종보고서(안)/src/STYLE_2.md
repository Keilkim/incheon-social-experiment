# STYLE_2 — 보고서형 formal 스타일 (재구성_시안_2 · 운영매뉴얼_시안_2 공통)

사용자 피드백(2026-11-08): 구도·도식 표현기법은 좋다. 색과 스타일이 "유치짬뽕"이다. 다음을 바꿔 **지금보다 아주 약간 더 깔끔하게** 만든다.
- 도형 외곽선 최소화
- 빗살(해칭) 채움과 솔리드 채움을 잘 구분해 쓰기
- 노란색 지양
- 사진에 청록 필터 쓰지 않기

**바꾸지 않는 것:** 구도, 도식의 종류와 배치, 글, 글꼴, 쪽 구성. 바꾸는 것은 색, 채움, 선, 모서리, 사진 처리뿐이다.

## 2. 채움 문법 — 솔리드와 빗살
| 의미 | 채움 |
|---|---|
| 주요 대상, 실측·결과, 현재(2차), 선택된 것 | **솔리드** `--navy` 또는 `--teal` |
| 비교 대상, 사전조사·기준값, 대조군, 계획, 보조 항목 | **빗살** — 45°, 선 0.3mm, 간격 1.3mm, 같은 계열 색 |
| 배경, 묶음, 비활성 | 옅은 면 `--sky2`, `#F3F6F8` |
| 미정·더미 자리 | 붉은 빗살 또는 붉은 글자. 점선 외곽선 대신 쓴다 |

구현:
- **SVG:** `<defs>`에 다음 패턴을 두고 `fill="url(#hatch-navy)"`로 쓴다.
  ```
  <pattern id="hatch-navy" width="1.3" height="1.3" patternUnits="userSpaceOnUse" patternTransform="rotate(45)">
    <rect width="1.3" height="1.3" fill="#fff"/>
    <line x1="0" y1="0" x2="0" y2="1.3" stroke="#1A2F4B" stroke-width=".3"/>
  </pattern>
  ```
  같은 방식으로 `hatch-blue`, `hatch-gray`, `hatch-red`도 만든다. 단위는 viewBox mm에 맞춘다.
- **HTML 상자:** `.hatch{background:repeating-linear-gradient(135deg,var(--hc,#2E5A87) 0 .3mm,#fff .3mm 1.3mm)}`
- 빗살은 데이터·분류를 나타낼 때만 쓴다. 빈 공간을 장식하는 데는 쓰지 않는다.
- 범례가 있는 도식은 범례에도 솔리드와 빗살을 같은 규칙으로 표시한다.

## 3. 선
- 면이 있는 도형(카드·박스·막대·원·칩)의 외곽선은 지운다. 면만으로 구분한다.
- 외곽선만 있던 도형은 옅은 면, 빗살, 또는 면 없음 중에서 고른다.
  - 점선 외곽선(계획·재실험·미정)은 빗살로 바꾼다.
- 남기는 선:
  - 표와 목록의 헤어라인 0.25mm, 표 윗괘선 0.5mm 남색
  - 연결선·화살표·축·눈금 0.3mm 이하
  - nav 괘선
- 모서리: 카드·상자는 `border-radius` 0.6mm 이하(현재 1.2–1.6mm). 칩은 0.6mm. 원형 요소는 그대로.

## 4. 사진
- 듀오톤(흑백 + 청록 multiply)을 쓰지 않는다. 원래 색을 살린다.
- `.duo img{filter:saturate(.88) contrast(1.03)}`, `.duo::after{display:none}`.
- 사진 위 글자 가독용 그늘이 필요하면 아래쪽으로 남색 그라데이션(투명→`rgba(19,36,58,.65)`)만 쓴다.
- 간지·표지: 청록 그라데이션 대신 `--navy-d` 단색 면(사진이 있으면 사진 + 아래 남색 그라데이션). 수평선은 흰색 40% 헤어라인으로 둔다.

## 5. 판정 칩·결론 상자
| 칩 | 모양 |
|---|---|
| `.judge.keep` 상설 | 솔리드 남색 + 흰 글자 |
| `.judge.fix` 수정 | 빗살(블루) + 남색 글자, 흰 글자 배경 처리 |
| `.judge.next` 중지 | 옅은 회색 면 + 남색 글자, 외곽선 없음 |
| `.judge.tbd` 미정 | 옅은 붉은 면 `#FBE9E8` + 붉은 글자, 외곽선 없음 |

- `.verdict`(노란 결론 상자): `--sky` 면 + 남색 글자, 모서리 0.
- `.band`: 남색 면, 강조 글자는 옅은 블루 `#C9D7E6`.

## 6. 작업 순서
1. `tools/restyle.py`로 색값을 기계적으로 바꾼다. 이 단계는 이미 적용했다.
2. 공통 CSS를 고친다: common.css, st_module.css, manual.css의 변수·duo·divider·judge·verdict·radius.
3. 파일마다 육안으로 손본다.
   - 노랑이 바뀐 자리가 어색하지 않은지 본다.
   - 외곽선을 지우고 솔리드·빗살 문법을 적용한다.
   - 범례를 맞추고, 대비(색 면 위 글자)를 확인한다.
4. 렌더해서 모든 쪽을 본다. `detect_tells.py`를 돌려 결과가 0건이어야 한다.

- 간지(사진 전면)는 위쪽 제목 가독용 옅은 남색 그늘을 허용한다(아래 그라데이션 + 위 옅은 그늘). 사진 가운데는 원색.
- 매뉴얼 편 색: 01 `#2E5A87` · 02 `#1A2F4B` · 03 `#4F7396` · 04 `#5B6B7A` · 서식 `#7F8B96`(흰 글자 대비 위해 `#8C98A3`에서 한 단계 어둡게). 옛 값 `#4A6378`·`#C9D7E6`(편 색으로 쓰인 곳)은 바꾼다.
- 남색 면 위 강조 글자·작은 점은 `#C9D7E6`. 흰 면 위에서 `#C9D7E6`은 면(fill)으로만, 글자·선으로 쓰지 않는다.
- 결과·최종 단계(도착점)는 솔리드, 계획·사전·비교는 빗살 — 순서가 있는 도식의 마지막 단계가 옅은 면으로 남아 '미완료'처럼 보이지 않게 한다.
- 팔레트 검사: `python3 tools/check_palette.py <파일…>` — 허용 목록 밖 색을 출력. 0줄 목표(사진 이미지 제외).
